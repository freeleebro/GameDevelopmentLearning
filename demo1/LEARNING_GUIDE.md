# Phaser + TypeScript Demo 学习指南

这个项目是一个基于 Phaser 3 和 TypeScript 的 2D 平台跳跃小游戏。它的价值不在于游戏内容本身，而在于展示了一个小游戏从初始化、场景切换、对象创建、物理模拟、输入处理到状态更新的完整链路。

你已经有编程基础，因此本文重点放在 Phaser 的运行模型、游戏开发中的对象关系、物理系统和代码组织方式，而不是重复讲解变量、循环、条件判断等通用语法。

## 一、项目整体结构

项目大致可以分为以下几层：

```text
index.html
  └─ 挂载游戏画布的 HTML 容器

src/main.ts
  └─ Phaser.Game 配置和场景注册

src/scenes/BootScene.ts
  └─ 启动或加载阶段

src/scenes/MenuScene.ts
  └─ 菜单、开始游戏输入、场景跳转

src/scenes/GameScene.ts
  └─ 玩家、平台、星星、物理、输入和分数逻辑
```

浏览器首先加载 `index.html`，其中的 `<script type="module">` 引入 `src/main.ts`。`main.ts` 创建 Phaser 游戏实例，Phaser 再按照注册顺序管理各个 Scene。

## 二、Phaser 游戏的启动过程

游戏入口中的配置对象决定了 Phaser 如何创建游戏：

```ts
const config: Phaser.Types.Core.GameConfig = {
  type: Phaser.AUTO,
  width: 800,
  height: 600,
  parent: "game-container",
  physics: {
    default: "arcade",
    arcade: {
      gravity: { x: 0, y: 300 },
    },
  },
  scene: [BootScene, MenuScene, GameScene],
};
```

需要重点理解的是：`width` 和 `height` 是游戏的逻辑坐标空间，不一定等于浏览器中最终看到的 CSS 像素尺寸。`scale.mode` 决定逻辑画面如何适配窗口；例如 `FIT` 会保持比例缩放，`RESIZE` 会让画布尺寸跟随窗口变化。

`parent` 表示 Phaser 创建的 canvas 挂载到哪个 HTML 元素。HTML 负责页面容器和基础布局，Phaser 负责 canvas 内的游戏渲染，两者是协作关系。

## 三、Scene 生命周期和代码组织

Phaser 的 Scene 可以理解为一个独立的游戏模块或画面。这个项目使用了启动场景、菜单场景和游戏场景。

### `create()`

`create()` 在场景开始时执行一次，适合完成：

- 创建精灵、文本、平台和物理组
- 注册输入
- 建立碰撞规则
- 初始化分数等状态
- 启动动画

### `update()`

`update()` 会随着游戏循环持续执行，适合完成：

- 读取持续输入状态
- 根据输入设置速度
- 检查角色是否可以跳跃
- 更新实时游戏逻辑

不要把每帧都不需要重复执行的初始化逻辑放进 `update()`，否则会不断创建对象、注册事件或产生额外开销。

### 场景切换

菜单场景通过以下代码进入游戏：

```ts
this.scene.start("GameScene");
```

场景切换通常意味着游戏状态的阶段变化。后续可以利用场景实现暂停界面、设置界面、关卡界面和结算界面。

## 四、Arcade Physics 物理系统

这个项目使用 Phaser 内置的 Arcade Physics。它适合平台跳跃、简单射击、收集物等不需要复杂刚体模拟的 2D 游戏。

### 重力

```ts
gravity: { x: 0, y: 300 }
```

Phaser 的坐标系中，`x` 向右，`y` 向下。因此 `y: 300` 表示物体持续向下加速，`x: 0` 表示没有水平重力。

重力是加速度，不是直接位移。物体的速度会随着时间变化，最终由物理系统计算位置。

### 动态物体和静态物体

玩家和星星是会受重力影响、会移动的动态物体：

```ts
this.physics.add.sprite(...)
this.physics.add.group(...)
```

平台通过 `this.physics.add.existing(platform, true)` 变成静态物理对象。静态对象通常不会被重力移动，但可以作为碰撞表面。

### 碰撞规则

碰撞需要明确指定参与碰撞的两个对象：

```ts
this.physics.add.collider(this.player, platform);
this.physics.add.collider(this.stars, platform);
```

这也是本项目中很重要的对象关系：重力只负责让星星下落，真正让星星停在地面上的是星星与平台之间的 collider。

`this.tweens` 是补间动画管理器，不是物理对象，因此不能传给 `setCollideWorldBounds()` 或 `physics.add.collider()`。

### 世界边界和弹性

```ts
this.player.setCollideWorldBounds(true);
```

或者对物理组设置世界边界，可以防止对象离开游戏世界。星星组还设置了 `bounceY: 0`，这样星星落到平台后不会反弹。

### 物理尺寸与显示尺寸

```ts
star.setDisplaySize(30, 30);
```

显示尺寸和物理 body 尺寸并不总是完全等价。后续如果出现碰撞看起来不准确的问题，需要检查 `body` 的尺寸、偏移量以及显示对象的缩放，而不能只看画面上的图片大小。

## 五、输入系统

方向键通过快捷方法创建：

```ts
this.cursors = this.input.keyboard!.createCursorKeys();
```

然后在 `update()` 中读取状态：

```ts
if (this.cursors.left.isDown) {
  this.player.setVelocityX(-300);
}
```

`isDown` 适合表示“按键当前是否持续按住”。而菜单中的按键事件：

```ts
const spaceKey = this.input.keyboard!.addKey(
  Phaser.Input.Keyboard.KeyCodes.SPACE
);

spaceKey.on("down", () => {
  this.startGame();
});
```

适合表示“按键刚刚按下”的一次性动作。注册 `aKey` 只是在监听按键，如果没有绑定 `aKey.on("down", ...)`，按 A 不会产生任何游戏行为。

这体现了两种不同输入模型：

- 状态输入：每帧查询，例如持续移动
- 事件输入：按下时触发，例如打开菜单或确认选择

## 六、补间动画和物理运动的区别

星星旋转使用 Tween：

```ts
this.tweens.add({
  targets: star,
  angle: 360,
  duration: 2000,
  repeat: -1,
  ease: "Linear",
});
```

Tween 是按照时间曲线改变对象属性，适合旋转、淡入、缩放、UI 动画和预设路径运动。

物理运动则由速度、重力、碰撞和阻尼共同决定，适合玩家、敌人、掉落物和子弹。

一个对象可以同时拥有 Tween 和物理 body，但两套系统修改同一个位置属性时要谨慎。通常应该让物理系统负责位置，让 Tween 只负责旋转、缩放或视觉表现。

## 七、碰撞回调和游戏状态

玩家碰到星星时，碰撞回调会调用 `collectStar()`。这个方法负责：

1. 销毁星星
2. 增加分数
3. 更新分数文本
4. 检查是否已经收集完所有星星
5. 显示胜利提示

这体现了一个常见的游戏代码模式：碰撞检测属于物理层，收集后的业务结果属于游戏状态层。后续项目变大时，可以进一步把分数、任务、生命值等状态抽成独立的数据对象或系统，减少 Scene 中的代码耦合。

## 八、TypeScript 在 Phaser 项目中的作用

TypeScript 主要帮助你在代码编辑和编译阶段发现对象使用错误。例如：

```ts
private player!: Phaser.Physics.Arcade.Sprite;
private stars!: Phaser.Physics.Arcade.Group;
```

这些类型让编辑器知道对象有哪些方法，也能及时发现把 `TweenManager` 当成物理对象传入的问题。

项目中的非空断言 `!` 有两类常见用途：

- `this.input.keyboard!`：告诉 TypeScript 键盘系统在当前配置下存在
- `player!`：表示属性会在 `create()` 中初始化后再使用

非空断言不会在运行时创建对象，也不会修复逻辑错误。它只是告诉编译器“这里由开发者保证不为空”，因此仍然需要保证初始化顺序正确。

## 九、阅读代码时应该重点追踪的关系

阅读 Phaser 项目时，不要只按文件顺序看语法，可以重点追踪以下关系：

### 对象的创建者和使用者

例如 `this.stars` 在 `create()` 中创建，之后被传给碰撞系统，又在 `collectStar()` 中统计数量。追踪一个对象的生命周期，比单独阅读某一行 API 更容易理解游戏逻辑。

### 谁修改位置，谁修改状态

- 物理系统修改物体位置和速度
- `update()` 根据输入修改速度
- Tween 修改动画属性
- 业务方法修改分数、生命值和关卡状态

### 初始化和每帧逻辑的边界

场景创建、事件注册、碰撞注册通常只做一次；输入状态和实时行为通常每帧处理。这个边界是 Phaser 项目能否稳定运行的关键。

## 十、当前项目还可以改进的地方

这个 Demo 已经覆盖了核心流程，但还有一些适合继续练习的方向：

- 将平台、星星和玩家的尺寸从硬编码改为配置数据
- 用真实纹理替代空纹理和色块
- 为玩家增加 idle、run、jump 等动画状态
- 给星星增加生成、刷新和掉落状态
- 将“收集星星”和“星星落地”设计成不同交互
- 增加重新开始、暂停和游戏结束流程
- 使用事件或独立管理器处理分数和游戏状态
- 使用摄像机实现大于屏幕尺寸的关卡

# 推荐的下一个 Demo：俯视角射击与敌人波次系统

建议下一个项目制作一个小型的“俯视角房间射击游戏”，而不是立即扩展当前平台跳跃项目。它能在保留 Phaser 基础结构的同时，引入更丰富的实体交互和系统组织，非常适合继续通过阅读代码学习。

## 推荐玩法

玩家在一个房间中移动，使用 WASD 控制方向，鼠标控制瞄准和射击。敌人从房间边缘生成并追踪玩家。玩家击败敌人获得分数，经过若干波敌人后进入下一关或显示胜利界面。

## 这个 Demo 将新增的技术

### 1. 多方向移动和鼠标瞄准

你会学习如何将键盘输入转换为二维方向向量，以及如何根据鼠标指针位置计算玩家或武器的旋转角度。

涉及：

- WASD 输入
- `Pointer` 鼠标坐标
- `Phaser.Math.Angle.Between`
- 速度向量归一化
- 角色朝向和武器旋转

### 2. 子弹系统

子弹适合使用 `Phaser.Physics.Arcade.Group` 管理。每次射击从对象池中取出或创建子弹，设置位置和速度；子弹飞出边界后回收。

涉及：

- 动态物理组
- 对象池思路
- 子弹与敌人的碰撞
- 生命周期和自动销毁
- 射击冷却计时

### 3. 敌人 AI

第一版不需要复杂寻路，只需要让敌人朝玩家移动。你会学习如何在 `update()` 中计算方向，并根据距离决定追踪、攻击或死亡。

后续可以加入：

- 近战敌人
- 远程敌人
- 不同移动速度
- 攻击冷却
- 简单状态机：追踪、攻击、受击、死亡

### 4. 生成器和波次系统

敌人不会全部在 `create()` 中写死，而是由波次系统动态生成。每一波有敌人数量、敌人类型和生成间隔，清空当前波后进入下一波。

这会练习：

- Phaser Timer Event
- 延迟和周期事件
- 波次状态管理
- 随机生成点
- 关卡节奏控制

### 5. UI 和游戏状态

增加生命值、分数、当前波次、弹药或冷却提示。你会进一步区分：

- 世界中的游戏对象
- 固定在屏幕上的 UI
- 游戏进行中、暂停、胜利和失败等状态

### 6. 摄像机和房间边界

可以让地图大于屏幕，通过摄像机跟随玩家，并用世界边界限制玩家活动范围。这会把当前项目中的固定画布概念扩展为可滚动的游戏世界。

### 7. 资源加载和动画

使用 `preload()` 加载图片、精灵表和音效，在 `create()` 中创建动画，在运行时根据状态切换动画。这样你会理解资源键、纹理、动画缓存和加载阶段之间的关系。

## 推荐的实现顺序

1. 创建房间地图和玩家
2. 加入 WASD 移动
3. 加入鼠标瞄准
4. 实现单发子弹和子弹碰撞
5. 创建一个会追踪玩家的敌人
6. 加入敌人死亡和分数增加
7. 加入敌人生成器和波次系统
8. 加入生命值、受伤和失败界面
9. 加入摄像机、真实资源和动画
10. 最后整理实体、系统和配置数据

## 交给下一个 Agent 时的建议要求

可以把需求描述为：

> 创建一个 Phaser 3 + TypeScript 的俯视角射击 Demo。要求包含启动场景、菜单场景和游戏场景；玩家可使用 WASD 移动、鼠标瞄准并点击射击；子弹使用 Arcade Physics Group 管理；敌人会追踪玩家并分波生成；包含碰撞、生命值、分数、胜利和失败状态。代码需要保持教学用途，每个核心系统拆分清晰，并为关键 API 写简洁注释。完成后提供项目结构、运行方式和学习重点。

这个项目完成后，你将从“单个玩家和平台的物理交互”进入“多个实体、对象池、AI、计时器、状态机和 UI 协作”的阶段，能够更系统地理解 Phaser 游戏代码是如何组织起来的。
